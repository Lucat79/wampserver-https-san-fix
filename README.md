# Wampserver HTTPS SAN fix

Fix missing Subject Alternative Names (SANs) in certificates generated by the native Wampserver HTTPS menu, and trust the installation's existing root CA on Windows.

[Istruzioni in italiano](README.it.md)

This is an independent community fix, not an official Wampserver release. The PHP correction resolved the reported Chrome error on the original Windows installation. The new PowerShell installer still needs an end-to-end Windows check; see [validation](docs/VALIDATION.md).

## Install

Requirements: Windows, Windows PowerShell 5.1 or later, an existing Wamp installation with native HTTPS initialized, and permission to administer the computer. The default installation path is `C:\wamp64`.

1. Download and extract this repository. Review the scripts before running them.
2. Exit Wampserver using its tray menu.
3. Double-click **`Install.cmd`** and accept the Windows administrator prompt.
4. Reopen Wamp. For sites with old certificates, disable and re-enable HTTPS from the Wamp menu to regenerate them. Restart Wamp services and the browser.

For future sites, use the normal Wamp HTTPS menu. No per-site mkcert command is required. One CA import covers certificates issued by that same CA, provided each certificate matches its hostname and is otherwise valid. A reinstall or CA replacement can require importing the new CA.

For another Wamp location, run from the extracted folder:

```powershell
.\Install.cmd -WampRoot 'D:\wamp64'
```

Preview without changing PHP or the certificate store:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Install-WampHttps.ps1 -WhatIf
```

Only install the root certificate, for example if the PHP correction is already applied manually:

```powershell
.\Install.cmd -RootOnly
```

The execution-policy option applies only to the launched PowerShell process; it does not change machine or user policy. Organization policies can still prevent execution.

## What the installer changes

- Checks that `scripts\changeToHttps.php` matches the provided original or patched source, ignoring only CRLF/LF differences. Unknown or modified versions are refused.
- Saves the original next to the installed PHP as `changeToHttps.php.san-backup-<id>` before replacing it. An already patched file is left in place.
- Reads **only** `bin\Certs\Cacerts\Certificat.crt` from the selected Wamp installation. Checks that it contains a single public certificate, is currently valid, is self-issued, has `CA:TRUE`, and permits certificate signing if a key-usage extension is present. These checks do not establish who created the CA; trust the Wamp installation you select.
- Displays the CA subject and thumbprint. Imports that exact certificate into **`Cert:\LocalMachine\Root`**, the Windows Trusted Root Certification Authorities store for all users. An identical thumbprint is not imported again.
- If root import fails after a PHP replacement, restores the original PHP from the backup. The backup is retained.

Installing a root CA allows this computer to trust certificates issued by it. Keep Wamp's CA private key private. This repository includes no CA certificates, private keys, site certificates or passwords; it never downloads a CA or modifies `openssl.cnf`, browser checks, or antivirus settings.

The package does not create a missing CA, create VirtualHosts, edit `hosts`, configure DNS, add `ServerAlias` SANs, renew old certificates, or regenerate existing site certificates automatically. Initialize native HTTPS in Wamp first if `Certificat.crt` is missing. Site certificate regeneration uses Wamp's existing menu.

## Why the patch works

The reported site certificate had the correct CN but no SAN. Trusting its issuing root fixed the authority error, but Chrome still reported `NET::ERR_CERT_COMMON_NAME_INVALID`.

The supplied `changeToHttps.php` signed a CSR using `openssl x509 -req` without explicitly supplying certificate extensions. The patch writes a temporary `Server.ext` file and passes `-extfile ... -extensions wamp_server` to the signing command. It adds:

```ini
[wamp_server]
basicConstraints = critical, CA:FALSE
keyUsage = critical, digitalSignature, keyEncipherment
extendedKeyUsage = serverAuth
subjectKeyIdentifier = hash
authorityKeyIdentifier = keyid,issuer
subjectAltName = DNS:<VirtualHost ServerName>
```

PHP selects `IP:` for a literal IP address and `DNS:` otherwise. The extension file is removed after successful signing. This does not claim that Wamp's VirtualHost UI or Windows filenames accept every IP format; IPv6 is tested at certificate-generation level only.

The original CA, certificate lifetime, key size and unrelated Wamp behavior are preserved. [Minimal upstream patch](patches/changeToHttps-san.patch) · [Maintainer report](docs/UPSTREAM_REPORT.md).

## Compatibility and recovery

This targets the exact source supplied with the original report. Its installed Wamp/Apache/PHP versions were not recorded; no blanket version compatibility is claimed. Supported normalized SHA-256 hashes are in [`scripts/source-hashes.json`](scripts/source-hashes.json). The earlier manually delivered patch is also recognized; the packaged PHP differs from it only by a modification-date comment. A Wamp update may replace the correction. If a newer source is refused, review the minimal patch against that source rather than bypassing the compatibility check.

To undo the PHP change, close Wamp and copy the desired `changeToHttps.php.san-backup-<id>` over `scripts\changeToHttps.php`, then reopen Wamp. Already generated certificates are unaffected.

Root trust is separate. To remove it intentionally, open `certlm.msc`, locate **Trusted Root Certification Authorities → Certificates**, and verify the exact thumbprint printed by the installer before deleting that certificate. Removing the CA's trust affects all local sites issued by it. The installer does not automatically remove certificates that were already trusted before it ran.

## Tests

Certificate tests require Python 3.9+, `cryptography`, and OpenSSL on `PATH`:

```sh
python -m pip install -r tests/requirements.txt
python tests/test_certificate_generation.py
```

On Windows, run the installer tests in Windows PowerShell:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tests\Test-Installer.ps1
```

These tests use temporary files and mock the certificate import; they do not change the Windows trusted root store. GitHub Actions is configured to run the certificate tests and Windows installer tests after publication. Workflow inclusion is not a claim that it has passed. See [validation and limitations](docs/VALIDATION.md).
